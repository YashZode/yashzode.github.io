    Case study · open source

    FactoryFlow.

    A secure OPC UA batch-production line, from operator screen to PLC to SQL history, built to keep working when the network drops, the database goes down or someone hits the E-stop.

    C# / .NET 8 + .NET Framework 4.8OPC UAWPFWinFormsSQL ServerNUnitAzure PipelinesMIT license
    The problem

    Connecting a screen to a machine is the easy part. Networks disconnect, SQL becomes unavailable and operators click while conditions change. The software must never show an assumed success, start a job twice, record a stale final weight or lose an event because a database call failed.

    What I built

    Seven projects: a .NET 8 OPC UA PLC simulator, a WPF operator HMI, a WinForms diagnostics tool, an optional telemetry collector, a shared OPC UA client, a SQL data layer with migrations, and the test suites.

    Architecture
    Decisions and tradeoffs
    Atomic start. The recipe target travels in the same OPC UA method call as the start command, so the two can never get out of step.
    Never lose an event. Production events go through a disk-backed outbox before SQL. Stop still works during a database outage, and each event has a stable ID, so a retry never creates a duplicate.
    Trust what the PLC reports. The screen follows observed PLC state, not the success of a write. After a reconnect the client rebuilds its subscriptions but never replays commands.
    Secure by default. Basic256Sha256 SignAndEncrypt with no unsecured endpoint, certificate validation always on, Windows-account roles and no stored passwords.
    Safe reset. The PLC rejects a fault reset while the guard is open or the E-stop is active. Acknowledging an alarm records who and when, but does not clear the cause.
    History keeps its meaning. Each batch stores a snapshot of recipe name, target, operator and UTC times, so editing a recipe never rewrites the past.
    Measured results local test runs, Oct 2026
    1.018 sto insert 25,000 distinct events; a duplicate retry added none
    19.8 msp95 batch-history query, 1,000 rows from a 10,000-batch fixture
    22 / 22NUnit tests passing on the PLC state machine
    52 / 52SQL + OPC UA integration checks passing, including faults, roles and reporting

    Scope, stated plainly: FactoryFlow is a simulation for development and demonstration. It has not been commissioned against a physical PLC, its software interlocks do not replace certified safety hardware, and the numbers above are local measurements, not sustained production load.
